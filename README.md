# CS2 CameraProbe

## Инструкции запуска / Getting started

- [Русский: требования, сборка и запуск](docs/QUICKSTART.ru.md)
- [English: requirements, build and launch](docs/QUICKSTART.en.md)

Прототип на C# / .NET 10 x64: переключение команд по кнопке, применение `spec_freeze_time` и `mat_fullbright`, сбор состояния и экспериментальное восстановление камеры. Пользователь подтвердил изображение после ручного ввода команд. Автоматический сценарий целиком ещё требует проверки в игре.

## Обновление камеры

Определение номера движка больше не использует фиксированный адрес: программа ищет уникальную сигнатуру в исполняемых секциях загруженной `engine2.dll`, проверяет границы адреса и соответствие файла загруженному модулю. Профиль игрока выбирается по build и SHA-256 загруженной `client.dll`, поэтому неизвестная или изменившаяся DLL останавливает запись. Включены отдельные профили 14188 SourceRevision 11064488/11076591 и профиль 14189 SourceRevision 11087167; архивный профиль 14186 сохраняет прежнюю проверку по build.

Общий режим `Start-ConVars.cmd` / `Start-CameraProbe.cmd` теперь удерживает локальную временную метку `m_flDeathTime` только в зафиксированном состоянии бага: здоровье больше нуля, `LifeState=2`, `PawnIsAlive=false`. Перед записью проверяются текущая сборка, машинный код выбранной ветки, схема, тип и идентификатор своего персонажа. Здоровье, команда и флаг жизни не меняются. При выходе из состояния или Ctrl+C собственное изменение восстанавливается; значение, заменённое самой игрой, сохраняется. Неопределённый результат прерванной записи оставляет журнал для восстановления.

Непрерывное слежение камеры подтверждено пользователем и записью `camera-experiment-20260929-020704-41800c70499541b7995f63bddd226330.jsonl`: после переходных кадров 94 из 94 отсчётов отличаются от ввода по yaw менее чем на один градус. Движение персонажа на сервере это исправление не восстанавливает.

Обновление `2026-09-29-health-zero`: после первоначального обнаружения бага при положительном здоровье восстановление продолжается при HP=0 для того же полного идентификатора персонажа, команды и раунда. Смена персонажа, команды, раунда, переход к наблюдателю или возрождение завершают текущую операцию. После перезапуска программы нужно заново воспроизвести баг при положительном здоровье. При HP=0 автоматически пишется диагностика движения; результат исправления камеры после смерти ещё требует проверки в игре.

Отдельные режимы DLL: `camera-experiment` — проверка до 15 секунд после ожидания нужного состояния (до 90 секунд); `camera-recover` — удержание до Ctrl+C; `camera-restore` — завершение прерванной проверки. Журнал `captures/camera-experiment.json` хранится рядом с запущенной DLL.

## Локальные ограничения двух ConVar

Для сборок движка **14185, 14186, 14188 и 14189** доступен отдельный режим:

```powershell
.\Run.ps1 -ConVars Inspect
.\Run.ps1 -ConVars Unlock
```

`Start-ConVars.cmd` запускает общий режим для сборок **14186, 14188 и 14189**: ConVars, камеру и обработку F6/F7 в одном окне. При каждом F6 программа открывает консоль на стандартной клавише `~ / Ё` и применяет две команды изображения. Во время freeze time за T/CT она также переключает команды и повторно применяет значения; из team 0 выполняется только восстановление изображения. `exec camera_probe` больше не нужен. Аналогичный запуск из PowerShell: `./Run.ps1 -Play -EnableSwitching`. Режим `-ConVars Unlock` сохраняется отдельно и не обрабатывает F6.

F6 в общем режиме автоматически выполняет следующие команды. В отдельном режиме `-ConVars Unlock` они вводятся вручную:

```text
spec_freeze_time 1000
mat_fullbright 1
```

Приложение меняет локальный бит `FCVAR_REPLICATED` только у `spec_freeze_time` и `FCVAR_CHEAT` только у `mat_fullbright`. Остальные флаги сохраняются. Команды выполняются обычным движком, включая его обработчики изменения значения. На сервере настройки не меняются; новые данные сервера могут снова изменить локальное значение. Дополнительные проверки движка этим не исключены.

**Проверено:** поиск двух переменных в работающей игре, типы int32/float32, чтение значений и флагов, тесты изменения битов и восстановления. Пользователь подтвердил результат ручного выполнения команд. Это отдельно от проверки автоматического F6.

Схемы **14186**, **14188** и **14189** получены из установленных версий игры с помощью cs2-dumper 0.1.3; происхождение записано рядом с каждой схемой. ConVars дополнительно проверяет реестр перед работой.

Окно режима Unlock должно оставаться открытым. Для отката значений сначала выполнить напечатанные приложением команды возврата (они основаны на значениях на момент запуска), затем нажать **Ctrl+C**. Ctrl+C восстанавливает **флаги**, а не изменённые через консоль числовые значения. Если принудительно закрыть окно, журнал остаётся в `artifacts/CameraProbe/captures/cvars-session.json`; восстановление флагов:

```powershell
.\Run.ps1 -ConVars Restore
```

Журнал записывается до изменения памяти. Общий режим автоматически восстанавливает прежний журнал ConVars при запуске. Сохранённые адреса проверяются по текущему процессу, времени его старта и найденным переменным. После перезапуска CS2 старый журнал архивируется без записи в новый процесс. Если восстановление не удалось, ошибка выводится, а журнал сохраняется.

`spec_freeze_time` управляет продолжительностью freeze cam после смерти; это не `mp_freezetime`. `mat_fullbright` — отладочный режим освещения. Изменение этих параметров само по себе не доказывает устранение сбоя камеры.

## Что работает в коде

- **F6** — применение `spec_freeze_time 1000` и `mat_fullbright 1` с проверкой значений, затем запрос перехода в другую команду и обратно с паузой 75 мс, запись состояния в течение 8 секунд. Доступно только с флагом `-EnableSwitching`, в окне CS2, за T/CT и во время freeze time.
- **F7** — запись состояния без переключения команд.
- **F8** — остановить текущую операцию. Если первая команда уже отправлена, игрок может остаться в другой команде; это фиксируется в журнале.
- **Ctrl+C** в окне приложения — выход.
- В режимах snapshot/watch выполняется чтение состояния только своего игрока. Проверка номера сборки; при несовпадении приложение останавливается. Запись флагов доступна только в отдельном режиме ConVars.

Факт отправки клавиш не означает, что сервер принял смену команды. Программа не обещает воспроизводимость бага и не определяет визуально, чёрная ли сцена.

## Запуск диагностики и переключения команд (14186/14188/14189)

1. Запустить поддерживаемую версию CS2 и включить консоль разработчика на стандартной клавише `~ / Ё`.
2. Открыть `Start-ConVars.cmd` или `Start-CameraProbe.cmd`. Оба запускают общий режим. PowerShell: `./Run.ps1 -EnableSwitching`.
3. Во время freeze time, играя за T/CT, нажать и отпустить **F6**. Программа применит настройки изображения, проверит значения и отправит `jointeam` туда и обратно. F9/F10 и старые cfg не используются.
4. Во время короткого ввода в консоль не нажимать другие клавиши. Shift/Ctrl/Alt/Windows должны быть отпущены. F8 отменяет операцию, Ctrl+C завершает приложение и восстанавливает флаги ConVar.

Если открыта консоль, чат или диалог, сначала закройте их. При смене команды консоль кратко остаётся открытой. При потере фокуса или отмене автоматический ввод прекращается; консоль может остаться открытой.

Для проверки фактического выполнения консоль сначала кратко устанавливает `spec_freeze_time` в 1001 (либо 1002), затем в требуемые 1000. Это не позволяет принять старые значения за подтверждение нового ввода. При прерывании между этими шагами программа покажет частичное состояние; числа автоматически не откатываются. Команда завершения: `spec_freeze_time 1000; mat_fullbright 1`.

Если консоль выключена или переназначена, проверка значений не пройдёт и смена команд будет отменена. Автоматическая отправка через консоль ещё требует проверки в игре. В коде больше нет отправки F10, которая ранее вызывала `cs_quit_prompt`.

Обновлённая отправка Enter: после текста выдерживается 120 мс, затем отправляется физический Enter на 80 мс. Это изменение сделано после подтверждения, что ручной Enter выполняет оставшуюся в строке команду. Проверка в матче ещё требуется.

Если приложение запущено во время обновления, сборка может быть подготовлена в `artifacts/CameraProbe.update`. Закройте старое окно CameraProbe через Ctrl+C и снова запустите любой из двух `.cmd`: лаунчер установит готовое обновление, сохранив журналы. CS2 закрывать не требуется.

Диагностика без изменения флагов: `./Run.ps1` и F7. Один снимок: `./Run.ps1 -Snapshot`. Изменить задержку: `./Run.ps1 -EnableSwitching -DelayMs 100`. Восемь секунд записи отсчитываются после смены команд. Старые конфиги и их резервные назначения сохранены на диске, но новой версии не нужны.

Результаты находятся в `artifacts/CameraProbe/captures/*.jsonl`. Для исследования заблокированного поворота нажать F7 в состоянии бага и двигать мышью 8 секунд. Записываются `InputViewAngles`, `PawnViewAngles`, `ObserverMode`, `ObserverLastMode`, `ForcedObserverMode`, параметры камеры и текущие значения двух ConVar. Камера читается через активный pawn контроллера, включая наблюдателя; проверяются полный handle и обратная ссылка. Ошибки чтения камеры сохраняются как предупреждения. Для F6 отдельно проверяются команда, freeze time и номер раунда, чтобы необязательные данные камеры не блокировали переключение. Снимки не атомарны; обнаруженные изменения состояния отбрасываются, но все гонки с движком исключить нельзя. Фокус опрашивается каждые 5 мс; более короткий уход и возврат могут остаться незамеченными.

## Сборка и проверки

Нужен установленный .NET 10 SDK; сторонние пакеты не используются.

```powershell
.\scripts\Build.ps1
```

Готовые файлы: `artifacts/CameraProbe/`. `Run.ps1` запускает DLL через выбранный `dotnet`, поскольку на этом компьютере переменная `DOTNET_ROOT` указывает на отдельную установку .NET 8. Это устраняет неоднозначность запуска .exe без изменения системных настроек.

## Отдельный эксперимент движения (не нужен в основном режиме)

`Test-Movement.cmd` запускает отдельную сборку, не требуя перезапуска CameraProbe. Оставьте общий режим с восстановлением камеры открытым. Воспроизведите потерю движения при HP=0, запустите тест, вернитесь в CS2 и нажмите пробел вне freeze time (без тайм-аута ожидания).

Тест однократно меняет локальное m_iHealth с 0 на 10000 на срок до 15 секунд, чтобы проверить прохождение клиентской ветки Health<=0. Исполняемый код игры не изменяется. Попробуйте WASD и прыжок. Это эксперимент, а не подтверждённое восстановление серверного движения. Если игра заменит значение здоровья, тест прекратится без повторной подмены. Серверное здоровье не изменяется этим инструментом.

При завершении и Ctrl+C исходный ноль восстанавливается только при совпадении персонажа, команды, раунда и состояния; новые значения игры сохраняются. Прерванная/неоднозначная операция оставляет журнал. Повторный запуск сначала пытается восстановить его; отдельное восстановление: `./scripts/Test-Movement.ps1 -Restore`. При неоднозначной смене контекста программа просит перезапустить CS2, а не записывает ноль в другого/возродившегося персонажа.

Журналы: `artifacts/MovementExperiment/captures/`. Проверка здоровья влияет на локальное состояние целиком, поэтому её эффект шире единственной ветки движения. Принятие движения сервером остаётся предметом проверки.


## Основной режим: автоматический локальный HP=10000

Сборка `2026-09-29-auto-hp` включает обработчик движения прямо в `Start-ConVars.cmd` и `Start-CameraProbe.cmd`. После HP=0 в ранее распознанном камерой состоянии бага локальное здоровье автоматически устанавливается в 10000 вне freeze time. Отдельный Test-Movement.cmd и пробел не нужны; не запускайте отдельный тест одновременно с основным режимом.

Обработчик сохраняет исходное значение в журнале и удерживает операцию до изменения состояния. Если игра заменяет здоровье, её новое значение сохраняется; при повторном HP=0 подходящее состояние может быть обработано снова. Ctrl+C завершает оба обработчика до восстановления ConVar. После возрождения, смены команды или раунда старое нулевое здоровье не записывается в новый контекст; при неоднозначном восстановлении журнал сохраняется.

Это локальное изменение, не установка здоровья на сервере. Движение после него ещё требует проверки. Данные сохраняются в `artifacts/CameraProbe/captures/movement-experiment-*.jsonl`.
